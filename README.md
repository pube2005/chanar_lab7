## Хэсэг E: Дүгнэлт (debrief)

### 1. Аль аялал хамгийн үр дүнтэй байв — согог тус бүр аль аялалаар олдов?
Энэхүү session-д хамгийн үр дүнтэй аялал нь Couch Potato (хоосон оролт) байлаа. Учир нь форм дээр гарчиг, зохиолч хоосон байсан ч ном нэмэгдэж байсан (BUG-01) болон оны хязгаар 1000-2100 байх ёстой байтал 990 гэсэн утгатай ном нэмэгдэж байсныг (BUG-03) энэ аялалаар илрүүлсэн. Supermodel (GUI) аялалаар Устгах товч улаан биш ногоон байгааг (BUG-02) олсон. Харин Saboteur (API) аялалаар хамгийн ноцтой согогийг оллоо: буруу JSON биетэй хүсэлт илгээхэд 400 алдаа буцаах ёстой байтал 200 OK буцааж, өгөгдлийг хүлээн авч байсан (BUG-04). 

### 2. Charter-аас гадуур санамсаргүй юу олдов? Юу шалгагдаагүй үлдэв?
Charter-аас гадуур санамсаргүй олдсон зүйл бол ижил нэртэй ном (жишээ нь "haant uls") давхардаж нэмэгдэж байсан явдал бөгөөд үүнээс гадна оны талбарт үсэг оруулахад "NaN" гэж харагдаж байв. Мөн анхны номнуудын он 1,971 гэх мэтээр таслалтай (comma) харагдаж байсан нь спецификациас зөрж байна. Харин 60 минутын дотор дараах зүйлсийг шалгаж амжаагүй: (1) Хайлтын систем том/жижиг үсгийг ялгаж байгаа эсэх, (2) Устгах үйлдлийн дараа "Нийт ном" тоолуур зөв шинэчлэгдэж байгаа эсэх, (3) Маш урт оролт хүснэгтийн layout-ыг эвдэж байгаа эсэх. Дараагийн session-ийн charter-т "Хайлтын логик ба тоолуурын бүрэн бүтэн байдал" гэсэн чиглэлүүдийг оруулж болно.

### 3. Эдгээр согогийн аль нь Лаб 1-ийн Playwright автомат тестээр баригдах байсан бэ, аль нь зөвхөн хүний нүдээр олдох байсан бэ?
Эдгээр согогуудын дотроос BUG-01 (Хоосон оролт) болон BUG-04 (API 400 биш 200 буцаах)-ыг Лаб 1-ийн Playwright автомат тестээр амархан барих байсан. Учир нь Playwright-ээр формыг хоосон орхиж "Нэмэх" товч дараад хүснэгтийн мөр нэмэгдэхгүй байхыг шалгах, мөн API руу буруу хүсэлт явуулаад статус код 400 байхыг шалгах боломжтой. Харин BUG-02 (Устгах товчны өнгө) болон BUG-03 (Онгийн хязгаар)-ыг автоматаар шалгаж болох ч, ялангуяа "Устгах" товчны өнгө нь визуал (нүдээр харах) болон UX-ийн асуудал тул хүний нүдээр илүү хурдан анзаарагддаг. Мөн "1,971" гэх мэт таслалтай формат, "NaN" гэж харагдах зэрэг нь тест бичих үед урьдчилан таамаглаагүй л бол зөвхөн exploratory тестээр (хүний нүдээр) илүү амархан олддог согогууд юм.
